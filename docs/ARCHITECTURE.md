# Архитектура проекта

Этот файл предназначен для краткой фиксации принятых технических решений. Его следует обновлять по ходу разработки, а не заполнять задним числом перед отправкой задания.

## Текущая структура

- `public/index.php` — единая публичная точка входа;
- `routes/web.php` — регистрация маршрутов;
- `src/Core` — минимальная инфраструктура приложения;
- `src/Controller` — сценарии HTTP-страниц;
- `src/Repository` — SQL-запросы и получение данных;
- `src/Service` — логика, которая не относится напрямую к HTTP или SQL;
- `templates` — Smarty-шаблоны;
- `database/migrations` — изменение структуры базы;
- `database/seeders` — тестовые данные.

## Направление зависимостей

Контроллер получает параметры запроса, вызывает репозиторий или сервис и передаёт готовые данные в представление. Шаблон не выполняет SQL и не принимает бизнес-решений. Репозиторий не выводит HTML и ничего не знает о Smarty.

## Журнал решений

### ADR-001. Единая публичная точка входа

Все HTTP-запросы направляются в `public/index.php`. Это позволяет централизованно загрузить окружение, маршруты и зависимости, а также не публиковать исходный код и конфигурацию через веб-сервер.

### ADR-002. PDO вместо отдельной библиотеки доступа к данным

Для небольшого тестового проекта достаточно встроенного PDO. Это сохраняет зависимости минимальными и явно показывает понимание подготовленных запросов и работы с MySQL.

### ADR-003. Связь статей и категорий many-to-many

У статьи может быть несколько категорий, поэтому связь хранится в отдельной таблице `category_post`. Такое решение соответствует требованиям и позволяет выбирать похожие статьи по общим категориям.

## Решения, которые предстоит зафиксировать

- формат и механизм миграций;
- формат объектов, возвращаемых репозиториями;
- способ получения трёх последних статей для каждой категории;
- поведение пагинации при несуществующем номере страницы;
- алгоритм сортировки похожих статей;
- правила обработки и хранения изображений.
