# План реализации блога

Документ фиксирует последовательность разработки, ожидаемый результат каждого этапа и точки проверки. После завершения этапа отмечайте его галочкой и обновляйте документацию, если фактическое решение отличается от плана.

## Общие принципы

- Используем PHP 8.1+ без PHP-фреймворков.
- Для базы данных используем PDO и подготовленные выражения.
- HTML формируется только через Smarty-шаблоны.
- Контроллер отвечает за сценарий страницы, репозиторий — за SQL, шаблон — за отображение.
- Не усложняем архитектуру паттернами, которые не помогают решить требования задания.
- Все входные параметры проверяем, все выводимые пользовательские данные экранируем.
- Каждый законченный этап оформляем отдельным осмысленным коммитом.

## Этап 0. Стартовый каркас — готово

Уже подготовлены:

- Composer и автозагрузка PSR-4;
- Smarty и базовый шаблон;
- минимальный маршрутизатор;
- SCSS и команда сборки стилей;
- Docker-окружение с PHP-FPM, Nginx и MySQL;
- структура каталогов проекта.

Коммит: `chore: bootstrap PHP Smarty project`.

## Этап 1. Спроектировать базу данных — готово

Нужно создать три таблицы.

### `categories`

- `id` — первичный ключ;
- `name` — название;
- `slug` — уникальная часть URL;
- `description` — описание;
- `created_at`, `updated_at` — даты создания и изменения.

### `posts`

- `id` — первичный ключ;
- `image_path` — путь или URL изображения;
- `title` — название;
- `slug` — уникальная часть URL;
- `description` — краткое описание для карточки;
- `content` — полный текст статьи;
- `views_count` — число просмотров, по умолчанию `0`;
- `published_at` — дата публикации;
- `created_at`, `updated_at` — служебные даты.

### `category_post`

- `category_id` — внешний ключ на категорию;
- `post_id` — внешний ключ на статью;
- составной первичный ключ из двух полей.

Также нужны индексы для `slug`, `published_at`, `views_count` и обоих внешних ключей. Таблицы должны использовать `utf8mb4`, а внешние ключи — явно выбранное поведение при удалении.

Результат этапа:

- SQL-миграция создаёт чистую базу с нуля;
- повторный запуск миграций не повреждает данные;
- связь статьи с несколькими категориями проверена вручную.

Рекомендуемый коммит: `feat: add initial database schema`.

## Этап 2. Добавить инфраструктуру работы с БД — готово

Задачи:

1. Создать класс подключения к MySQL через PDO.
2. Брать параметры только из переменных окружения.
3. Включить режим исключений, реальные подготовленные запросы и `utf8mb4`.
4. Добавить консольные команды или простые PHP-скрипты для запуска миграций и сидеров.
5. Выводить понятную ошибку приложения без публикации пароля, SQL и трассировки в production-режиме.

Результат этапа: приложение устанавливает соединение с MySQL, а база разворачивается одной документированной командой.

Рекомендуемый коммит: `feat: add PDO database connection and migrations`.

## Этап 3. Реализовать сидеры — готово

Подготовить не менее:

- 4 категорий;
- 15–20 статей с разными датами публикации и просмотрами;
- нескольких статей, относящихся сразу к двум категориям;
- одной категории без статей для проверки главной страницы.

Сидирование должно быть повторяемым: перед заполнением тестовых данных таблицы очищаются в безопасном порядке либо используются предсказуемые идентификаторы.

Результат этапа: одной командой получается набор данных, достаточный для проверки сортировки, пагинации и похожих статей.

Рекомендуемый коммит: `feat: add category and post seeders`.

## Этап 4. Доработать маршрутизацию и обработку ошибок — готово

Планируемые маршруты:

- `GET /` — главная;
- `GET /category/{slug}` — категория;
- `GET /post/{slug}` — статья.

Маршрутизатор должен поддерживать динамический сегмент `slug`. Для неизвестного адреса и отсутствующей записи нужна отдельная страница `404`.

Результат этапа: каждый маршрут вызывает свой контроллер, неизвестный URL возвращает HTTP-код `404`.

Рекомендуемый коммит: `feat: support dynamic routes and error pages`.

## Этап 5. Репозитории и модели данных — готово

Минимальный набор:

- `CategoryRepository`;
- `PostRepository`;
- простые объекты `Category` и `Post` либо документированные массивы данных.

Репозитории должны содержать всю работу с SQL. В контроллерах и шаблонах SQL быть не должно. Следует избегать N+1-запросов при загрузке категорий статей.

Результат этапа: данные можно получить и проверить отдельно от HTML.

Рекомендуемый коммит: `feat: add blog repositories`.

## Этап 6. Главная страница — готово

Требования:

- показывать только категории, в которых есть опубликованные статьи;
- для каждой категории выводить три последние статьи по `published_at`;
- добавить ссылку «Все статьи», ведущую на страницу соответствующей категории;
- корректно обработать полностью пустую базу.

Для тестового задания лучше выбрать читаемый запрос или небольшое число понятных запросов, чем преждевременно усложнять SQL. Принятое решение и его компромисс стоит описать в `docs/ARCHITECTURE.md`.

Рекомендуемый коммит: `feat: implement blog home page`.

## Этап 7. Страница категории — готово

Страница должна выводить название, описание и список статей.

Сортировка задаётся query-параметром:

- `?sort=date` — сначала новые статьи;
- `?sort=views` — сначала популярные статьи.

Значение сортировки обязательно проверяется по белому списку. Нельзя напрямую подставлять пользовательское значение в `ORDER BY`.

Пагинация:

- фиксированное число статей на странице, например 6;
- параметр `page` приводится к положительному целому числу;
- ссылки пагинации сохраняют выбранную сортировку;
- для страницы за пределами диапазона выбирается заранее описанное поведение: `404` либо последняя доступная страница.

Рекомендуемый коммит: `feat: add category sorting and pagination`.

## Этап 8. Страница статьи и похожие материалы — готово

При открытии статьи нужно:

1. Найти её по `slug`.
2. Увеличить `views_count` на единицу атомарным SQL-запросом.
3. Получить все связанные категории.
4. Вывести изображение, название, описание, полный текст, дату и число просмотров.
5. Получить до трёх других статей хотя бы с одной общей категорией.

Текущую статью необходимо исключить из похожих. Если подходящих статей меньше трёх, выводится фактическое количество без заглушек.

Рекомендуемый коммит: `feat: implement post page and related posts`.

Рекомендуемый коммит: `style: add responsive blog interface`.
